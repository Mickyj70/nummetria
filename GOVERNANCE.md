# Governance

Nummetria is currently maintainer-led and developed in public.

## Roles

- **Contributors** propose issues, documentation, code, tests, and reviews.
- **Maintainers** triage work, review changes, manage releases, and protect the
  project's product, privacy, and compatibility commitments.

Roles are earned through sustained, constructive participation. Maintainers may
invite contributors who demonstrate sound judgment, reliable follow-through,
and respect for the community.

## Decisions

Routine decisions are made through issue and pull-request discussion. The
maintainers seek rough consensus and are responsible for making a final call
when consensus is not possible.

Changes that are difficult to reverse—such as storage formats, public JSON
contracts, provider interfaces, privacy behavior, and license changes—require a
documented Architecture Decision Record before implementation.

## Merging and releases

- All changes use pull requests and required checks.
- Pull requests are squash merged.
- Maintainers may not merge known failing or undocumented behavior.
- Releases follow the published roadmap and changelog.
- Security releases may use a private preparation process before coordinated
  disclosure.

## Project assets

Repository access, package publication, release signing, domains, and deployment
access should never depend permanently on one person's undocumented machine or
credentials. As the maintainer group grows, access will be distributed with the
least privilege needed for each role.
